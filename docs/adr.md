# 01. return domain entity from CreateAccount/Client

* state: accepted

## Context

Нужно удобное возвращаемое значение для тестов/uc после создания (по сути регистрации в bd)

## Options considered

### return Guid

pros

- Глубокая инкапсуляция, нет выставления наружу объекта

cons

- Неудобно тестировать моками
- При создании объекта и потенциальной доп. информации в useCase придется вызывать bd

### return domain entity

pros

- все reversed cons guid

cons

- Потенциально утечка сущности и изменение состояния (только в памяти)

## Decision

Выбрал объект, т.к основа состояния - это из бд, потенциальная утечка и изменение объекта не отразиться на работе
приложения, даже при учете, что состояние объекта в памяти поменяется, изменения в бд без SaveChanges не попадут

# 02. decimal type for everywhere

* state: accepted

## Context

Изначально все началось с `rate`, он представлялся как `double type`, хотя все операции с деньгами были `decimal type`.
`double type` представляется как `binary floating point` с основанием 2 (мантисса*2^exp), из-за этого получается, что
`rate` - число, которое представлено не как произведение только двоек в знаменателе, представляется неточно.
`decimal type` представляется как целое число и сдвиг (целое_число_96_бит × 10^ (-scale))

## Decision

Поменял на `decimal`. Из-за того, что `rate` мог представиться неправильно и добавить хвост, итоговое значение могло
быть округленно в неверную сторону.
